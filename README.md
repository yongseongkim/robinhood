# 나랏일보고서 · robinhood

국회의원 정치자금, 지방의회 경비, 신고재산, 법안·표결과 국가재정을 기간·재원·출처별로 조회하는 대시보드입니다. 저장소는 [robinhood](https://github.com/yongseongkim/robinhood), 공개 서비스 이름은 나랏일보고서입니다. 서버·웹 디렉터리와 패키지는 기존 `robin-hood` 이름을 사용합니다.

## 새 웹과 API 실행

Pencil의 통합 화면을 `robin-hood-web`(React·TypeScript)과 `robin-hood-server`(FastAPI·PostgreSQL)로 구현했습니다. 실제 수집본을 읽으며 인물·상호의 표시 이름은 기본 가명입니다. 기존 `pipeline/`과 원본 데이터는 계속 사용합니다.

수집한 원본·가공 데이터, 로컬 DB, 생성된 `site/data/`, 인증정보와 캐시는 Git에 포함하지 않습니다. 새 체크아웃에서는 기존 데이터 볼륨을 복원하거나 아래 수집 파이프라인을 실행한 뒤 조회 인덱스를 생성해야 합니다. 데이터가 없는 동안 API의 준비 상태는 503입니다. 격리된 예제 입력을 사용하는 테스트는 수집 자료 없이 실행할 수 있고, 실제 수집본 대조 테스트는 인덱스가 있을 때 실행됩니다.

```bash
# 터미널 1 · Python 3.12+ / uv
cd robin-hood-server
uv sync
# 운영 DB를 쓰려면 .env.example을 .env로 복사하고 DATABASE_URL 설정
uv run --env-file .env robin-hood migrate
uv run --env-file .env robin-hood index
uv run --env-file .env robin-hood serve
```

```bash
# 터미널 2 · Node.js 22.12+
cd robin-hood-web
npm ci
npm run dev
```

기존 메인 PostgreSQL의 `robin_hood` 전용 스키마를 사용합니다. DB URL 없이 로컬 SQLite로 확인하려면 `--env-file .env`와 `migrate`를 생략하세요. 실제 운영 연결·상시 실행 안내는 [배포 안내](deploy/README.md)에 있습니다.

웹은 `http://localhost:5173`, API 명세는 `http://localhost:8000/api/docs`입니다. 웹에서 `npm run build`를 실행하면 API 서버의 `http://localhost:8000`에서도 웹을 제공합니다. 개발 프록시는 같은 출처의 `/api` 요청을 API 서버로 전달합니다.

- 화면: 내 지역 지도, 의원·정당 목록과 프로필, 지방의회 직책 경비, Top 10·항목·월별 그래프, 자주 결제한 장소와 거래 상세, 나라 살림, 데이터·출처·분석 기준.
- OCR 정정: 서버 job에서 추출된 표 텍스트만 Codex로 정리하는 선택 단계를 제공합니다. 원문은 보존하고 정정 이력을 따로 저장합니다. SDK·ChatGPT 로그인과 기능 활성화가 필요합니다.
- 주기 수집: 서버 디렉터리에서 `uv run --env-file .env robin-hood worker --interval-hours 24`. DB에 다음 실행 시각·이력을 저장하고 실패 시 1·5·15분 재시도합니다. Linux 서비스 설정은 `deploy/systemd/`에 준비했으며 실제 활성화는 아직 하지 않았습니다.
- 지도: `robin-hood-server/.env.example`의 `NAVER_MAPS_CLIENT_ID`를 설정하면 네이버 Maps SDK를 사용합니다. 키가 없으면 행정구역 지도를 표시합니다. 현재 장소 데이터는 구 단위이며 정확한 가게 좌표는 없습니다.
- 검증: 서버에서 `uv run pytest -q`, 웹에서 `npm run build`와 `npm run test:e2e`. 기존 파이프라인은 루트 `.venv/bin/python -m pytest -q tests`.

설정·수집·API는 [서버 설명](robin-hood-server/README.md), 지도·경로·브라우저 검사는 [웹 설명](robin-hood-web/README.md)을 참고하세요. 아래 내용은 기존 정적 사이트와 수집 자료 설명입니다.

## 기존 정적 사이트

### 바로 보기

`site/index.html`을 브라우저로 여세요 (`file://`로 열어도 동작합니다). 데이터는 `site/data/*.js` 조각을 `<script>`로 불러옵니다.

정적 호스팅(GitHub Pages, S3 등)에 `site/` 폴더를 그대로 올리면 됩니다.

| 화면 | 주소 | 보여주는 것 |
|---|---|---|
| 우리 동네 | `#/region` | 지도에서 지역을 고르면 그 지역 국회의원(정치자금·의정활동)과 구의회 |
| 나라 살림 | `#/budget` | 나라가 어디서 돈을 얻고(국세 세목·기금·세외) 어디에 쓰는지(16대 분야·부처·세부사업), 해마다의 총수입·총지출, 국가채무 |
| 정치인의 돈 | `#/money` | 국회의원 정치자금의 수입 유형·지출 분류, 지방의회 업무추진비의 사용 분류별 금액 |
| 순위판 | `#/rank` | 국회의원·지방의회 지출 Top 10(총액·항목별·식사 지표), 직책별·사람별 업무추진비, 여러 사람이 함께 쓰는 가게와 그곳의 최다 지출자, 같은 식당 평소 가격보다 크게 비싼 결제, 국회의원 재산(순재산·증감·부동산·증권·채무 순위, 부동산이 있는 시·군·구) |
| 많이 쓴 곳 | `#/outliers` | 같은 연도·분류 안에서 유난히 많이 쓴 지출 주체 (통계 기준, 위반 판단 아님) |
| 탐지 규칙 / 데이터 출처 / 읽는 법 | `#/rules`, `#/sources`, `#/guide` | 규칙 명세, 원자료와 수집 시각, 화면 읽는 법 |

## 다시 만들기

```bash
uv venv .venv -p 3.12 && uv pip install --python .venv/bin/python -r pipeline/requirements.txt
pipeline/run_all.sh            # 수집 → 파싱 → 정규화 → 탐지 → 사이트 데이터
pipeline/run_all.sh --no-fetch # 이미 받은 원본으로 재처리만
.venv/bin/python -m pytest -q tests  # 정규화·개인정보 마스킹·탐지 규칙·OCR 표 복원 테스트
```

직책 보유자(의장단·상임위원장, 기수별)는 각 의회 공식 홈페이지의 선출 기록에서 수집해 연결했습니다.
서울 구의회 23곳은 `pipeline/districts/g1~g3.py`가 2022-07(제9대)부터 수집하며, 수집된 의회는 `data/staging/councils/<slug>.json`으로 자동 등록됩니다. 강북구의회 재수집에는 Playwright와 Chrome이 필요합니다(서버가 스크립트 요청을 막음). 스캔·이미지 PDF(강남·강동·용산·중랑·서울시의회 일부, 2022년 이후 117개)는 `pipeline/parse_ocr.py`가 macOS Vision OCR로 읽어 5,600여 행을 추가합니다(이 컴퓨터 안에서 처리, 외부 전송 없음). 인쇄된 합계가 있는 40개 파일 중 21개가 원 단위까지 일치했고(서울시의회 5/5, 용산 15/17), 강동은 읽은 합계가 인쇄 합계의 중앙값 97.7%입니다. OCR 행에는 "스캔본 OCR로 읽음" 표시가 붙고, 합계가 일치한 파일만 신뢰도 "보통", 나머지는 "낮음"입니다. OCR 결과 캐시는 `data/ocr/`에 저장됩니다.

"우리 동네" 지도(`#/region`)는 제22대 국회의원 지역구 254곳과 서울 25개 구를 그립니다. 경계: 통계청 SGIS 행정동 경계(공공누리 제1유형)를 vuski/admdongkor가 가공한 자료(CC BY 4.0), 선거구: 오마이뉴스 2024_22_elec_map(MIT). `pipeline/build_geo.py`가 미리 투영한 SVG 경로와 시·군·구 인접 정보를 `site/data/geo.js`로 만들고, 인접 정보는 "관할·인접 지역 밖 사용" 규칙에도 쓰입니다.

원본 수록 지출 433,172건 중 서로 다른 공개 파일에 다시 실린 같은 거래 670건을 빼고 432,502건을 분석합니다. 탐지 규칙 28개, 탐지 결과 4,705건.

열린국회정보: 의원 인적사항은 정당·지역구·위원회·당선 횟수 등 공적 정보만 저장하고 생년월일·전화·이메일·보좌진·약력은 받지 않습니다. 정치자금 자료의 의원과는 이름+지역구로 연결합니다. 현직 20명은 정치자금 자료(2023~2024년) 이후 재보궐·승계로 들어와 연결할 자료가 없습니다. 동명이인은 표결 기록의 정당이 한결같고 같은 이름·정당이 한 명뿐일 때만 나누고(제21대 김병욱 두 명), 그래도 구분되지 않으면 연결하지 않고 개수만 셉니다. 이미 연결된 의원에 다른 의원 코드를 이름만으로 붙이지 않습니다(2026년 보궐로 들어온 동명이인 박지원). 표결은 `collect_votes.py`가 처리된 의안마다 1회씩(1초 간격) 받아 쌓고, 다시 실행하면 새로 처리된 의안만 받습니다.

재산: 국회공보 PDF(893쪽)를 직접 읽고, 의원마다 항목 합계 = 소계, 소계 합계 - 채무 = 총계인지 확인합니다(287명 전원 통과). 정보공개센터가 정제한 스프레드시트와 총계·부동산 항목을 대조해 모두 일치했습니다. 정보공개센터 자료는 CC BY-NC-ND라 검증에만 쓰고 사이트에는 싣지 않습니다. 부동산 위치는 시·군·구와 읍·면·동까지만 싣고 지번·건물명·동호수는 저장하지 않습니다. 금액은 신고가액(공시가격 등)이라 시세와 다를 수 있고, 고지거부한 부모·자녀 재산은 빠집니다.

열린재정: 금액은 모두 원 단위로 바꿔 저장합니다(원자료 단위는 조원·억원·천원이 섞여 있음). 해마다의 총수입·총지출은 12월 누계가 있는 연도만 결산 값으로 씁니다. 예산(본예산·국회확정)과 결산은 섞지 않고 화면에 어느 쪽인지 적습니다. 규칙 명세는 사이트의 "탐지 규칙" 페이지와 `pipeline/rules.py`에 있습니다.

## API 인증키 (SOPS + GCP KMS)

API 키(`assembly_api_key` 열린국회정보, `openfiscal_api_key` 열린재정)는 환경변수로 설정하거나 프로젝트 루트의 `credentials.yaml`에 SOPS로 암호화해 둡니다. SOPS 암호화 설정은 로컬 `.sops.yaml`에 둡니다. 두 파일 모두 Git에서 제외하므로 새 환경에서는 직접 설정해야 합니다.

여는 데 필요한 것: 그 KMS 키에 대한 복호화 권한(`roles/cloudkms.cryptoKeyEncrypterDecrypter`)과 gcloud ADC 로그인(`gcloud auth application-default login`).

```bash
sops credentials.yaml                       # 편집기에서 값을 바꾸고 저장하면 다시 암호화됨
.venv/bin/python pipeline/credentials.py                     # 값은 출력하지 않고 읽히는지만 확인
.venv/bin/python pipeline/credentials.py openfiscal_api_key
```

파이프라인은 `pipeline/credentials.py`의 `get("assembly_api_key")`처럼 키를 메모리에서만 복호화해 씁니다. 환경변수(`ASSEMBLY_API_KEY`, `OPENFISCAL_API_KEY`)가 있으면 그 값이 우선합니다. 키를 읽지 못하면 해당 수집만 건너뛰고 이전에 받은 원본으로 계속 만듭니다. 원본 manifest·로그·사이트(`site/`)에는 키가 들어가지 않습니다. 열린국회정보 이용약관상 인증키는 발급받은 본인만 쓸 수 있으니 공유하지 마세요.

## 원칙

- 탐지 결과는 **추가 확인이 필요한 패턴**이지 위반·부정의 증거가 아닙니다. 법령 기준 대조 / 통계 기준 / 같은 값 반복 / 단어 일치 / 공개자료 점검을 구분해 표시합니다.
- 탐지 결과로 지출 주체에 점수를 매기지 않습니다. 순위판은 공개된 금액·건수를 같은 재원·같은 기간 안에서 그대로 줄 세운 것이고, 판단은 보는 사람에게 맡깁니다.
- 재원(정치자금, 의회운영업무추진비, 의정운영공통경비, 사무국 업무추진비)은 서로 합산하지 않습니다.
- 공동경비를 의원 개인 지출로 귀속하지 않습니다. 직책 업무추진비에는 그 기간의 직책 보유자를 의회 홈페이지 기준으로 표시하되, 개인 지출로 표시하지 않습니다.
- 모든 탐지 결과 → 근거 거래 → 원본 문서(URL, sha256)까지 추적됩니다.
- 생년월일·개인 주소·전화번호·후원인 정보는 게시하지 않고, 개인에게 지급된 금액의 사용처는 "개인(비공개)"로 바꿉니다.
