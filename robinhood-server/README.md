# robinhood-server

나랏일보고서의 FastAPI 조회 API와 수집 worker입니다.
운영 데이터는 메인 PostgreSQL의 전용 `robinhood` 스키마에 저장합니다.
PostgreSQL 연결 URL을 생략하면 로컬 개발용 SQLite를 사용합니다.
URL을 설정한 상태에서 연결에 실패하면 API는 조회 오류를 반환합니다.

## 설정과 실행

의존성 설치, 환경변수 설정, 최초 수집과 로컬 실행 절차는 [공통 설치 안내](../docs/INSTALL.md)에 있습니다.

`DATABASE_URL`에는 기존 메인 DB의 조회용 연결 URL을 지정합니다.
서비스 테이블은 `ROBINHOOD_DATABASE_SCHEMA`가 지정한 전용 스키마에 만듭니다.
기본값은 `robinhood`이며 `public`과 시스템 스키마는 사용할 수 없습니다.
권한을 나눌 때는 적재·마이그레이션·수집 잠금에 쓸 연결 URL을 `ROBINHOOD_JOB_DATABASE_URL`에 지정합니다.
두 연결에서 같은 DB와 전용 스키마를 사용해야 합니다.
URL에는 비밀번호가 포함될 수 있으므로 저장소에 커밋하지 않습니다.

API는 `/api/docs`에 명세를 제공하고, 웹 빌드가 있으면 같은 서버가 `robinhood-web/dist`도 제공합니다.
설정 파일은 uv의 `--env-file` 옵션으로 읽으며 운영에서는 환경변수를 직접 주입할 수 있습니다.

최초 배포에서는 `migrate`로 PostgreSQL 스키마를 준비한 뒤 `collect`로 자료를 수집해 조회 DB에 발행합니다.
이미 정규화한 자료를 다시 적재할 때는 `index`를 사용합니다.
스캔 PDF 수집에 필요한 환경은 [OCR 실행 환경](../docs/INSTALL.md#ocr-실행-환경)에서 확인합니다.

## 저장 구조와 발행

- `subjects`, `merchants`, `documents`, `transactions`, `findings`에 지출 주체, 거래처, 원문 정보, 거래, 탐지 결과를 각각 저장합니다.
- `extras`와 `metadata`에는 신고재산, 의정활동, 재정통계, 지도, 분류·출처·검토 이력을 JSONB로 저장합니다.
- `job_runs`는 수집 이력과 시도 횟수를, `job_schedule`은 다음 실행 시각과 연속 실패 횟수를 기록합니다.
- `schema_migrations`에 적용한 스키마 변경 이력을 기록합니다.

PostgreSQL 모드에서 `index`는 정규화 자료로 임시 SQLite 인덱스를 만들고 검증한 뒤 `COPY`로 PostgreSQL에 적재합니다.
작업이 끝나면 임시 파일을 삭제하고 API는 PostgreSQL에서 자료를 읽습니다.
현재 원본 PDF·XLSX와 OCR 캐시는 `data/`에 보관합니다.
객체 저장소는 향후 보관 경로로 고려하고 있습니다.
조회 DB에는 정규화한 데이터와 원문 URL·해시·수집 시각을 저장합니다.

발행은 하나의 PostgreSQL 트랜잭션에서 처리합니다.
기존 데이터 삭제와 새 적재 중 하나라도 실패하면 모두 롤백합니다.
읽기 API는 요청마다 `REPEATABLE READ READ ONLY` 트랜잭션을 사용하므로 한 응답에서 이전 자료와 새 자료가 섞이지 않습니다.
이 동작을 위해 TRUNCATE 대신 DELETE를 사용합니다.
운영 DB의 autovacuum을 유지하세요.
모든 변경은 전용 서비스 스키마 안에서 이뤄집니다.

수집과 인덱싱은 같은 세션 advisory lock을 사용하므로 여러 호스트에서 동시에 발행할 수 없습니다.
잠금을 획득한 연결에서 자료를 발행하며, 그 연결이 끊어지면 발행도 실패합니다.
따라서 수집에는 직접 연결 또는 세션 풀을 사용해야 합니다.
API가 PgBouncer의 트랜잭션 풀을 쓰면 `ROBINHOOD_JOB_DATABASE_URL`에는 직접 연결 URL을 지정합니다.

## 주기 실행

`serve`는 조회 API를 제공하고, `worker`는 별도 프로세스에서 수집 파이프라인을 실행합니다.
실행 명령은 [주기 수집 안내](../docs/INSTALL.md#주기-수집)에 있습니다.

worker는 시작할 때 다음 실행 시각을 확인하고, 작업을 마치거나 건너뛴 뒤 30초를 기다렸다가 일정을 다시 확인합니다.
저장된 일정이 없으면 바로 수집하고, 재시작하면 저장된 일정부터 확인합니다.
기본 설정에서 다음 정규 수집은 작업 완료 24시간 뒤입니다.
실패하면 1분, 5분, 15분 뒤에 차례로 재시도하고, 세 번 모두 실패하면 다음 정규 주기를 기다립니다.
재시도할 때는 이미 받은 원본·첨부 파일을 재사용하면서 파이프라인 전체를 다시 실행합니다.

외부 CronJob/스케줄러에서는 `robinhood run-due`를 1분마다 실행할 수 있습니다.
DB에서 실행 시각을 확인하고 다른 수집자가 있으면 건너뛰므로 worker와 같은 중복 방지 규칙을 따릅니다.
`collect`는 시각과 관계없이 한 번 실행하는 운영 명령입니다.

worker가 SIGTERM이나 SIGINT를 받으면 진행 중인 작업을 마치고 종료합니다.
수집 파이프라인이 기본 제한 시간인 2시간을 넘기면 해당 프로세스 그룹을 종료하고 실패로 기록합니다.
다음 작업이 잠금을 획득했는데 이전 실행 상태가 여전히 `running`이면 이전 실행을 `interrupted`로 기록합니다.
로그는 `var/logs/`에 권한 `0600`으로 저장합니다.
API에서 공개하는 것은 실행 상태와 이력이며, 작업 시작과 로그 열람은 서버에서 수행합니다.

Linux에서 서비스를 활성화하는 절차와 DB 역할별 권한은 [배포 안내](../deploy/README.md)에 있습니다.

## 실제 자동 갱신 범위

| 자료 | 주기 실행 때의 동작 | 범위·조건 |
|---|---|---|
| KA-money | 저장소 목록과 blob SHA로 변경된 보고분을 찾고 XLSX 형식과 해시를 검증 | 2023~2025년 보고분을 수집하며 2024년은 제21·22대로 구분. 원본이 잘못 덮어써졌으면 정상 공개 이력에서 복구. 2025년 보고분부터 지출 건수·합계를 지출 전용 파일과 대조하며 새 서식은 별도 지원 필요 |
| 서울시의회·25개 구의회 | 게시판 새 게시물·첨부 수집 및 재파싱 | 이미 받은 동일 첨부는 재사용하므로 수정본 전체 재검사는 아님. 강북구는 Chrome 필요 |
| 직책 보유자 | 공식 의회 홈페이지 기록 재수집 | 확인되는 직책·기간만 연결 |
| 법안·표결 | 의원 명부와 법안을 갱신하고 새로 처리된 의안의 표결을 수집 | 열린국회정보 인증키 필요. 저장본을 재사용하되 처리일로부터 30일 이내이고 표결이 비어 있으면 재조회 |
| 국가재정 | 열린재정 API와 공식 연간 국가결산 PDF를 수집 | API 인증키 필요. 재작년까지의 연도별 API 파일은 재사용. 2025년 결산은 한국재정정보원 자료집 10·13쪽(PDF 20·23쪽)에서 확인하며 새 자료집은 출처와 표 위치를 검증한 뒤 추가 |
| 신고재산 | 정기재산공개 국회공보를 파싱하고 수시신고를 해당 공보의 총계와 연결 | 정기신고와 수시신고의 기준일을 구분 |
| 지도 | 없는 원본·출처 문서를 내려받고 경계 생성 | 정해진 경계 버전의 원본을 재사용. `--no-fetch`에서는 다운로드 생략 |
| OCR | 신규 스캔본 처리 | macOS Vision 또는 Linux Tesseract. Linux에서 새로 읽은 행은 원문의 인쇄 합계와 대조 후 집계 |

조회 API와 화면은 발행된 최신 정치자금 보고분과 지방의회 수집 연도를 기본으로 선택합니다. `report`, `year`, 기간 필터로 과거 수집본도 조회할 수 있습니다. 당해 연도 지방의회 자료는 공개된 달까지만 수록될 수 있습니다.

`succeeded`는 설정한 파이프라인이 끝나 조회 데이터를 발행했다는 뜻입니다.
수집을 건너뛴 기관의 자료는 이전 수집본일 수 있으므로 화면에서 출처별 수집 시각과 대상 기간을 확인합니다.
수집 중 일부 출처의 갱신에 실패해도 조회 자료가 검증을 통과하면 발행할 수 있습니다.
이때 `sourceChecks`에 실패한 출처가 있으면 worker는 `partial`을 기록하고 재시도 일정을 적용합니다.
`failed`로 기록된 적재 실패는 이전 조회 데이터를 유지합니다.

## OCR 표 텍스트 정정

수집 worker는 OCR 표를 파싱한 뒤 정규화하기 전에 선택적으로 텍스트 정정을 실행합니다.
Codex에는 표에서 추출한 텍스트만 전달하며, PDF·이미지·파일 경로·원문 URL·상세 주소는 입력에서 제외합니다.
모델은 읽기 전용 임시 작업 공간에서 실행합니다.
원본 PDF·XLSX·API 응답과 `data/staging/*_ocr.jsonl`은 그대로 보관합니다.

```bash
# robinhood-server/에서
uv sync --extra ocr-correction
# 모델 호출·DB 저장 없이 대상과 입력 크기만 확인
uv run --env-file .env robinhood ocr-correct --plan
# 정정을 활성화하면 worker가 OCR 표를 파싱한 뒤 정정 단계를 호출한다.
uv run --env-file .env robinhood worker --interval-hours 24
```

`ROBINHOOD_OCR_CORRECTION_ENABLED=true`로 활성화합니다.
Codex Python SDK를 사용하며 ChatGPT 로그인 상태를 확인합니다.
API 키 인증으로 전환하지 않습니다.
전용 `ROBINHOOD_OCR_CODEX_HOME`에 정상 로그인된 실행 환경을 준비하세요.
사용량은 해당 계정의 한도에 따릅니다.
모델을 지정하지 않으면 계정의 기본 설정을 사용하며, 재현 가능한 운영 설정에는 `ROBINHOOD_OCR_MODEL`을 고정하는 편이 좋습니다.

기본 설정에서는 실행당 최대 5묶음, 묶음당 최대 40행·20,000자, 호출당 최대 120초까지 허용합니다.
원본 내용·추출 결과·프롬프트·모델 설정이 같은 완료 기록이 있으면 해당 결과를 재사용합니다.
한 번에 검토하지 못한 행에는 다음 실행에서 정정할 때까지 추출값을 사용합니다.
수동 `ocr-correct`는 정정본을 준비하며, 다음 `collect` 또는 `collect --no-fetch` 실행의 정규화 단계에서 조회 자료에 반영합니다.

기존 행의 거래처 표기·집행목적·결제수단에서 문구와 띄어쓰기, 잘못 배치된 텍스트 열을 정정할 수 있습니다.
거래처 이름을 바꾸려면 같은 표에 근거가 있거나 공백·문장부호만 달라야 합니다.
금액·날짜·시간·인원·재원·직책·주소와 텍스트 안의 숫자는 보존합니다.
이 값을 바꾸거나 행을 추가·삭제·병합하자는 제안, 근거가 부족한 제안은 검토 대기로 기록합니다.
정정 후에도 추출 당시의 OCR 신뢰도를 유지합니다.

PostgreSQL의 `ocr_corrections`에는 원본 해시, 추출 행 사본, 프롬프트·모델 설정, 수정 전후 문구, 사유·근거 문구, 검증 결과를 저장합니다.
로컬 모드에서는 `var/ocr-corrections.sqlite3`를 사용합니다.
정규화 단계는 `var/ocr-corrections.json`으로 내보낸 검증 완료 정정본 중 추출 행의 해시가 일치하는 것만 적용합니다.
수치와 행 수는 보존하고 중복 거래는 정정 전 문구를 기준으로 판별합니다.
조회 자료를 다시 발행해도 정정 이력은 보존합니다.

정정 대상은 로컬 OCR 파서가 지방의회 표에서 추출한 행입니다.
KA-money의 2차 OCR 엑셀과 파서가 행을 추출하지 못한 표는 제외합니다.
초기 입력 점검에서 117개 문서의 5,614행이 203묶음으로 나뉘었고, 가장 큰 묶음은 8,587자였습니다.
모든 원본 파일의 해시를 확인했습니다.
이 점검은 입력 범위와 크기를 측정한 것으로, 실제 모델의 정정 품질은 별도 검증이 필요합니다.
정정 기능을 꺼도 같은 설정으로 검증을 끝낸 정정본은 재사용합니다.

정정본을 적용한 거래는 상세 화면에 원문 보존 여부와 텍스트 정정 여부를 표시합니다.
추출·정정·적재를 검증한 뒤 중간 파일을 정리하는 정책은 별도로 정하며, 현재 원본과 OCR 캐시는 자동으로 삭제하지 않습니다.

## API와 상태 확인

| `/api/v1` 기준 경로 | 내용 |
|---|---|
| `/meta`, `/geo`, `/overview` | 데이터 범위·지도·지역 요약 |
| `/members`, `/subjects/{id}` | 의원 목록·지출·수입·재산·법안·표결 |
| `/member-rankings?report=ka:2025-22&party=` | 의원·정당 첫 화면의 지출·신고재산·정치자금 수입 순위, 재산 종류별·정당별 재산 Top 10 |
| `/councils`, `/councils/{id}` | 의회·직책·반기별 경비 |
| `/rankings`, `/places`, `/places/{id}` | Top 10·분포·자주 결제한 장소 |
| `/transactions`, `/transactions/{id}`, `/documents/{id}` | 거래·원문 근거 |
| `/fiscal`, `/sources`, `/findings` | 재정통계·출처·규칙·확인 표시 |

`/fiscal`은 `basis=actual|budget|proposal`, 선택적인 `year`를 받습니다. 연도가 없으면 수집된 최신 연도(결산은 우선 연간 자료가 확인된 연도)를 선택합니다. 월별 API에 12월이 없으면 한국재정정보원의 공식 연간 국가결산 표를 사용하고, 확인되지 않은 연간 수입 구성은 null로 둡니다. 응답의 `availableYears`는 기준별 선택 가능 연도이고 `trends.series`는 총규모·분야·부처별 시계열과 전년 대비 금액·증감률·비중 변화를 담습니다. 결산의 연간 비교에는 12월 누계만 포함하며, 정부안은 전년도 확정 예산과 비교하고 두 점의 기준을 각각 표시합니다. 누락 항목이나 분모가 0인 증감률은 null입니다.
| `/jobs/status`, `/jobs/history?limit=20` | 최근 실행 상태·다음 실행·실행 이력 |

금액 단위는 원입니다.
응답의 `scope`에서 조회 기간, 집계 종류, 재원과 해당 보고서 ID를 확인할 수 있습니다.
금액은 재원별로 집계하고 다른 문서에 다시 실린 거래와 문서의 대상 기간을 벗어난 거래는 합계에서 제외합니다.
자료가 빠진 달의 금액은 `null`입니다.
인물·상호는 공개자료의 원래 이름으로 검색하고 표시합니다.
개인 수령인은 `개인(비공개)`로 표시하고 개인사업자 번호의 뒷자리는 가립니다.

`/member-rankings`는 한 읽기 스냅샷에서 지표별 범위를 따로 반환합니다. 지출은 선택한 회계보고분이며, 재산은 최신 수집 공보의 신고 기준일과 신고대상 가족을 포함한 순재산입니다. 정당별 Top 10은 전체 재산 자료를 정당별로 나눈 뒤 계산하고 각 정당의 전체 수록 인원으로 중앙값을 구합니다. 정치자금 수입은 선택한 대수에 연결된 의원의 해당 연도 수입을 대수 구분 없이 합산하며, 이월·누계·계좌 간 이체를 제외하고 차입금·본인 자산 등은 포함합니다. 개인 소득 자료는 없으므로 정치자금 수입이나 재산 증가액으로 추정하지 않습니다. 미수집 값은 순위에서 제외하며 실제 0원·음수 값은 유지합니다.

`assetCategories`는 부동산·증권·예금·가상자산별 Top 10으로, 정당 필터를 적용하고 지출 보고연도와 별개인 재산 기준일을 씁니다. 부동산은 토지·건물 소계에서 전세·임차권을 빼며 임차권 구분·금액이 불명확한 기록은 제외합니다. 증권은 주식 외 증권도 포함하는 공보 소계이며 예금에는 별도 정치자금 계좌를 넣지 않습니다. 종류별 금액은 채무 차감 전 신고가액으로 신고대상 가족을 포함하고 고지거부 재산은 제외합니다. 해당 항목의 유효 금액이 있는 인원으로 순위·중앙값을 계산하며 누락을 0원으로 바꾸지 않습니다.

종류별 순위에는 토지·건물 개별 순위와 채무·현금도 포함합니다. `assetChanges`는 최신 연말 공보의 기준연도와 증가·감소 Top 10을 반환하며, 증가액은 양수 내림차순, 감소액은 음수 오름차순입니다. 0원·누락은 양쪽에서 제외하고 연말 기준일을 확인할 수 없으면 연간 순위를 만들지 않습니다. 현재 수집본은 2025년 말 기준으로 이전 연도 공보는 보존하지 않아 연도 선택을 제공하지 않습니다.

`assetConcentration`은 부동산·증권 신고액을 총자산(순재산 + 채무)으로 나눈 비율이며 `value`·`median`은 0~1, `amount`는 분자 원화 금액, `grossAssets`는 분모 원화 금액입니다. 분모가 0원 이하이거나 누락·불일치가 있는 기록은 제외하고, 전체 항목 검증을 통과한 기록에서만 미등재 채무를 0원으로 해석합니다. 비율 합계 `total`은 null입니다. `partyWealth`는 개인 정당 필터와 무관하게 전체 공개기록의 정당별 순재산 중앙값(`median`)·산술평균(`mean`)·수록 인원·중앙값 기준 순위를 반환합니다. 평균은 Top 10을 추리기 전 해당 정당의 유효한 순재산 합계를 전체 수록 인원으로 나눈 값입니다. 미수집은 제외하고 실제 0원·음수는 포함합니다.

스키마 변경은 `robinhood migrate`로 먼저 적용합니다. 기존 컬럼 제거는 새 API·worker 교체 후 `robinhood migrate --post-deploy`로 적용합니다. ArgoCD에서는 각각 PreSync·PostSync Job이 실행합니다. migration 004가 표시용 이름 컬럼과 이름 치환 메타데이터를 제거하며 원래 이름과 거래·수집 이력은 보존합니다. SQLite 조회 인덱스는 `robinhood index`로 다시 생성합니다.

`/api/health`에서 조회 가능 여부를 확인하고, `/api/v1/jobs/status`에서 `state`, `stage`, `attempt`, `nextRunAt`과 출처별 확인 시각을 확인합니다.
운영 알림은 별도 연동이 필요합니다.
