# 설계 메모

운영 구성은 `robinhood-server`(FastAPI·PostgreSQL·수집 worker)와 `robinhood-web`(React·TypeScript)입니다. 기존 메인 PostgreSQL의 전용 `robinhood` 스키마에 저장합니다. `DATABASE_URL`이 없는 로컬 개발에서만 SQLite를 사용합니다. 이전 `site/`는 별도 정적 배포용으로 유지합니다.

```text
raw → staging → normalized + findings → 검증용 임시 인덱스
                               ├→ PostgreSQL COPY/원자적 발행 → FastAPI → React
                               └→ legacy site/data
PostgreSQL job_runs + job_schedule ← worker / 외부 스케줄러 run-due
```

공통 정규화 모델을 검증한 임시 인덱스는 발행 후 삭제됩니다. 주체·거래처·문서·거래·확인 표시는 관계형 테이블, 재산·법안·재정·지도·출처 정보는 JSONB로 저장합니다. 운영 API는 PostgreSQL을 직접 읽고 연결 장애 시 로컬 데이터로 전환하지 않습니다. 원본 PDF/XLSX·OCR 파일은 디스크 또는 객체 저장소의 대상입니다.

새 자료의 DELETE·COPY·무결성 검사는 같은 트랜잭션으로 커밋/롤백합니다. API의 `REPEATABLE READ READ ONLY` 요청은 한 버전의 자료를 유지합니다. 여러 호스트의 수집·발행은 세션 advisory lock으로 직렬화하고 발행도 잠금 소유 연결에서 처리합니다. 연결을 잃은 작업이 다른 연결로 발행을 계속하지 않습니다. 원본 캐시와 DB의 백업은 별도로 관리합니다.

worker는 DB의 `job_schedule`을 30초마다 확인합니다. 성공 완료 후 24시간, 실패 시 1·5·15분의 최대 세 차례 재시도, 이후 다음 정규 주기를 적용합니다. 재시작 시 저장된 일정을 복원합니다. 외부 CronJob은 `run-due`를 호출할 수 있습니다. 실행 이력은 `job_runs`에 저장하며 API에서 조회할 수 있고 공개 작업 시작 API는 없습니다. Linux systemd 서비스 설정은 준비돼 있지만 운영 연결/활성화는 수행하지 않았습니다.

웹 개발 시 Vite가 `/api`를 프록시하고 운영 빌드는 API가 정적 파일과 SPA fallback으로 제공합니다. 응답 `scope`는 재원·시작·종료일과 보고분·월·연간·기준일을 명시하며 재원은 합산하지 않고 결측 금액은 null입니다. 가명은 표시 계층의 선택이고 원본은 보존합니다. NAVER Maps에는 공개 키 ID와 구별 대표 좌표를 사용합니다. 가게 정확 좌표·Geocoding·Toss 플랫폼 연동은 별도 범위입니다.

전체 수집기의 지원 연도·첨부 캐시·인증키·macOS OCR 조건은 [서버 안내](../robinhood-server/README.md)에 명시했습니다. 배치 성공을 모든 출처가 최신이라는 보장으로 쓰지 않습니다. 운영 권한과 실행 방법은 [배포 안내](../deploy/README.md)에 있습니다.

## OCR 정정 계층

`parse_ocr.py`의 추출 결과를 서버 job의 Codex 단계가 표 텍스트만 입력받아 검토합니다. PDF·이미지·원문 URL·파일 경로를 모델 입력으로 보내지 않습니다. 원본 파일은 서버에서 해시만 확인하고 `raw/`와 기존 OCR 추출 JSONL을 덮어쓰지 않습니다.

`ocr_corrections`는 `doc_id`, 원본/추출 해시, 프롬프트·모델 설정, 추출 행 사본, 수정 전후·근거·검증 결과를 저장합니다. 조회 테이블을 교체할 때 유지되는 별도 감사 이력입니다. 검증된 텍스트 정정본을 `var/ocr-corrections.json`으로 내보내고 정규화가 추출 행의 해시를 대조해 적용합니다. 정정 전후 수치·기간·주체·재원과 행 수를 유지하며, 기존 중복 판단은 정정 전 문구를 사용합니다. 거래 상세는 정정본 적용을 표시하고 OCR 신뢰도를 그대로 유지합니다.

SDK는 기존 ChatGPT 로그인만 사용하고 키 인증이면 중단합니다. 변경 없는 입력은 재호출하지 않으며 묶음·행·입력 길이·시간을 제한합니다. `ROBINHOOD_OCR_CORRECTION_ENABLED`로 새 호출을 켜고, 꺼진 상태에서도 저장된 동일 설정의 정정본은 재사용합니다. 아직 실제 모델 실행이나 상시 AI 처리를 활성화하지 않았습니다. SDK 구성·로그인·운영 DB 연결은 배포 설정을 따릅니다.

## 문제별 처리

- **기관마다 다른 엑셀 컬럼**: 헤더 행(`연번`)과 보조 헤더(`일자/시간/상호명/주소`)를 합쳐 열 이름으로 매핑. 관악구 서식 6종을 확인했다. 매핑 실패 파일은 보고서에 남는다.
- **PDF**: 마포구는 텍스트 PDF라 OCR 없이 표 추출. 병합 셀·줄바꿈은 복구하고 `parse_confidence`로 표시.
- **스캔·이미지 PDF (OCR)**: `ocr.py`가 페이지를 300dpi로 렌더링해 macOS Vision(ko-KR, 정확도 우선, 언어 보정 끔)으로 글자와 위치를 읽고 `data/ocr/`에 캐시한다. `parse_ocr.py`가 머리글 위치로 열을 잡고(띄어 읽기·붙어 읽기·한 글자 오독 허용), 날짜·시간·금액·결제수단은 모양으로 먼저 판별하며, 한 상자로 붙은 칸은 글자 위치로 나눈다. 한 자리 인원 숫자는 해당 칸만 잘라 키워 다시 읽는다. 날짜 칸이 빈 행은 병합 셀로 보고 앞 행 날짜를 이어받는다(신뢰도 낮음). 표 위·아래의 인쇄된 합계와 비교해 파일별 일치 여부를 남긴다. 사용자 칸은 그 의회의 텍스트 자료에 나오는 직책명과 같을 때만 쓰고, 성명이 섞이면 버린다.
- **OCR 자료 (KA-money)**: 원자료를 고치지 않고 `ocr: true`로 표시. 사업자번호 1자리 OCR 오류는 대표 상호가 같을 때만 합친다(116개). 번호와 상호가 전혀 안 맞으면 번호를 버리고 `BIZNO_NAME_CONFLICT` 표시.
- **같은 업체의 여러 상호**: NFKC·법인 표기 제거·공백/괄호 제거한 상호키 + 사업자번호로 묶음. 상호키만 같은 경우 신뢰도 "낮음". 주소가 빈 행은 같은 공개 자료에서 그 상호가 한 시·군·구에서만 나오면 그 지역 거래처로 본다(예: 서울시의회 '서울시청매점'이 둘로 갈라지던 문제).
- **동명이인 의원**: KA-money 의원번호를 그대로 키로 사용 (README의 동명이인 구분 반영).
- **정당 변경**: 회계보고(대수)별 정당을 따로 보관. 연중 변경은 원자료에 없음.
- **직책 변경**: 직책 + 기수(전·후반기)로 주체를 나눠 서로 다른 사람의 지출이 섞이지 않게 함.
- **직책 보유자**: 의회 공식 홈페이지(의회연혁·역대 의장단·의원 약력)에 적힌 선출 기록만 써서 직책×기수에 보유자를 붙인다(`collect_roles.py` → `data/staging/role_holders.json`, 원문 스냅샷은 `data/raw/roles/`). 선출일 이전처럼 보유자를 확인하지 못한 기간은 "미확인"으로 남긴다. 사람 페이지는 직책 이력을 모아 보여줄 뿐이고, 지출은 여전히 직책 단위이며 개인 지출로 표시하지 않는다.
- **같은 거래의 중복 수록**: 정확히 같은 행을 B4 규칙으로 표시. 영수증 번호(정치자금)·문서 id(지방의회)로 "실제 반복"과 "적재 중복"을 구분. 같은 파일이 다른 게시글에 재첨부되면 최초 게시글에만 귀속하고 공개 점검(E1)으로 표시.
- **취소·환급**: 음수 행을 같은 주체·거래처·절대금액의 원거래와 짝지어(-180~+7일) 순지출 계산. 짝 없는 반환은 B5로 표시. 반환을 수입으로 처리한 경우는 지출 자료에 없음(KA-money 한계).
- **원본 변경·삭제**: 수집기가 sha256을 기록하므로 재수집 시 바뀐 파일을 알 수 있다. 전체 파이프라인이 결정적이라 `run_all.sh`로 재생성하면 탐지 결과도 다시 계산된다. 탐지 id는 규칙·주체·근거 거래로 만든 해시라 근거가 같으면 id가 유지된다.
- **결측·신뢰도**: 인원 없으면 1인당 계산 생략, 시간 없으면 심야 판단 생략, 비교 표본이 작으면 통계 비교 생략.
- **개인정보**: 생년월일 형식의 사업자번호 칸 → 개인으로 보고 사용처를 가림. 인건비 분류 사용처 가림. 자유 텍스트의 전화번호·이메일 가림. 주소는 시군구까지만. 개인사업자 번호 뒷자리 가림. 참석자 명단 파일은 파싱하지 않음. 정치자금 수입(후원인)은 유형별 합계만.

## 지역(지도)과 의회 레지스트리

- `pipeline/councils.py`: 기본 3개 의회 + 구의회 수집기가 쓰는 `data/staging/councils/<slug>.json`을 합친 레지스트리. 대수 계산(`term_base_2018`), 사이트 표기, 관할 지역이 여기서 나온다.
- 관할 지역: 훈령의 "근무지와 경계를 접한 시·군·구까지"를 행정구역 경계에서 계산한다. 선으로 맞닿은 이웃(`adjacent`)과 한 점으로만 맞닿은 이웃(`touches`, 예: 관악구-영등포구)을 모두 포함한다(표시를 덜 하는 보수적 해석).
- 국회의원 ↔ 선거구: KA-money의 지역명과 오마이뉴스 선거구 경계의 이름을 맞춘다(제22대 254/254 일치). KA-money는 의원별 최신 지역명만 갖고 있어 선거구가 바뀐 제21대 의원 일부는 지도에 연결되지 않는다.
- 제21대 현직 판정: 2023년 파일(현직만 수록)에 있는 사람만 제21대 의원으로 본다. 2024년 상반기 파일에만 있는 109명은 제22대 총선 예비후보 기간의 회계다.

## 화면별 계산

- **정치인의 돈** (`money.js`): 정치자금 수입은 유형(후원회 기부금·선거비용 보전·기탁금 반환 등)별 합계만 내고, 계좌 간 이체·이월 누계처럼 중복될 수 있는 항목은 따로 표시해 합계에 넣지 않는다. 지출은 회계보고의 대분류, 지방의회는 `council_category`(식사·카페·경조사·성금·물품 등) 기준. 재원끼리 합치지 않는다.
- **많이 쓴 곳** (B6 규칙): 같은 연도·같은 대분류 안에서 P95 이상이면서 중앙값의 3배·1천만 원 이상(정치자금), 구의회 직책은 월평균이 P95 이상이면서 중앙값 2배 이상이고 6개월 이상 자료가 있을 때만. 서울시의회는 구의회와 규모가 달라 비교군에서 뺀다. 점선 분포(strip plot)로 비교군 전체를 함께 보여준다.
- **나라 살림** (`fiscal.js`): 본예산·국회확정(예산)과 12월 누계(결산)를 구분한다. 부처별 총지출은 최근 회계연도의 세부사업 상위 항목을 접어서 붙이고, 다음 연도 정부안이 있으면 별도 표시한다.
- **순위판** (`rank.js`, `build_rank.py`): 금액·건수·비율을 같은 재원·같은 기간 안에서만 줄 세운다(점수 아님). 국회의원은 연도별 정치자금(제21·22대 의원만), 평균·비율 순위는 식사 20건 이상. 지방의회는 직책·기수별, 그리고 의회 홈페이지 선출 기록이 있는 의회(관악·마포·서울시의회)에 한해 직책을 맡은 사람별로 의회운영업무추진비를 모은다. 월평균의 개월 수는 공개 기간 안 날짜만 센다. 가게는 사업자 거래처만 세고 전국 체인·결제대행·배달앱은 '장소'에서 빼며, 식대로 분류됐어도 상호가 광고·여행사 등이면 식당 집계에서 뺀다(`common.CHAIN_STORE`, `NOT_FOOD_PLACE`).
- **재산** (`parse_assets.py` → `assets.json`, `build_assets.py` → `assets.js`): 국회공보 PDF의 표를 pdfplumber로 읽는다. 사람 머리글(소속·직위·성명)과 표 행을 쪽 안의 위치 순서로 합치고, 쪽 경계에서 나뉜 행(관계·금액이 한 번 더 찍히고 명세만 이어짐)은 새 주소로 시작하지 않을 때만 앞 행에 붙인다. 사람마다 항목 합계 = 소계, 소계 - 채무 = 총계를 확인한다. 전세(임차)권은 건물 항목에 신고되지만 소유가 아니라 따로 센다. 의원 연결은 정치자금 자료의 제22대 주체 중 이름이 한 명뿐일 때만.
- **가격 차이**: 같은 식당에서 인원이 적힌 다른 결제들의 1인당 금액 중앙값을 그 가게의 평소 가격으로 보고, 2배 이상이면서 1인당 1만5천원 이상 비싼 결제를 고른다. 결제 8건 이상·평소 1인당 8천원 이상인 식당만, 구내식당·매점·도시락과 OCR 행은 뺀다. 시중가 비교가 아니다. 물품 구매는 수량이 거의 없어 단가 비교를 하지 않는다. 조달청 나라장터 물품의 시중가 비교는 나라장터 품목·단가 API와 시중가 자료(별도 인증키)가 필요하다.
- **의정활동**: 대표발의 법률안은 처리 결과를 가결·대안반영·임기만료 폐기·철회·부결·심사 중으로 묶는다. 표결 참여율 = (찬성+반대+기권) / 전체 표결 기록. 반대·기권은 모두, 나머지는 최근 20건만 사이트에 싣는다.
